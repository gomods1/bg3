# PLAYTEST

Coverage map and session log (template_rpg 23). `SCREENS.md` lists what exists; this file records
**what was actually exercised, with which character, choices and game path**, what was never
exercised, and which assumptions could break on other characters, classes, branches or areas.

Rule: a row is "verified" only with a speech-log excerpt (and a screenshot when layout matters)
from the running game. Everything else is "untested", even when the code exists.

Game 4.1.1.7398727 (Patch 8 hotfix 9), Script Extender v32, NVDA, game language Spanish,
2560x1600 borderless, keyboard/mouse UI (no controller connected).

## 4. Assumptions that other characters, classes or paths could break

Check these first when something goes silent or wrong on a new path:

1. **Widget names** come from the XAML (x:Name or ContextName). Pages in the Gustav, GustavX and
   Patch8 paks were never extracted (`xaml_index.py` only indexed Game.pak): screens from those
   paks have no XAML index entry, so the generic fallback has no labels there.
2. **Router "front widget"** = last visible non-HUD, non-overlay child of ContentRoot. New overlays
   (e.g. "Overlay", "AlwaysOnTopOverlay" were added as met) can steal the front: add them to
   `Game/Ui.lua` OVERLAYS or HUD when found.
3. **HUD list** in `Game/Ui.lua` is from the nautiloid HUD; other HUD widgets (e.g. photo mode,
   splitscreen) are unknown.
4. **Character creation** reads Selectable*/Selected* generically, but spell/passive selectors
   and the appearance page are not handled at all (3.2).
5. **Hotbar**: only KeyboardHotBars of type Common/Class/Item/Custom are listed; spell hotbars of
   casters are probably the Class bar but spells with slots/upcast variants (SpellVariants,
   SpellUpcast) are not handled.
6. **Targeting** assumes the target is a combatant from the turn order bar; targeting items,
   corpses or a character outside combat is not supported. The ground is the place cursor's job
   (Projectile/Throw types get "A place on the ground"; other types go straight to the cursor;
   `Projectile_Jump` is special-cased in Combat/Actions PLACE_ONLY).
7. **Travel** clicks the ground: assumes the camera follows the controlled character and that the
   route's first 12 m are clickable; ladders are climbed by clicking the ladder entity (aimed 1-5 m
   above its foot) and waiting 2.5 s of stillness; other portals (jumps) still stop the trip.
   Path requests now allow ladders and portals (CanUseLadders/CanUsePortals): routes may include
   jumps the character cannot make as a click.
8. **Clicks after keyboard use**: the game swallows the first mouse button press after keyboard
   input (measured 2026-09-24: the second click always counted, motion alone did not help). The
   bridge sends an X1 side-button press (bound to nothing) before every click. If a new game
   version binds X1, clicks break again: check `tools/console/dump_bindings.lua` output. Game
   commands are still preferred over clicks.
9. **Door state** comes from server Osiris queries (`IsOpened`, `IsLocked`); in multiplayer the
   client may not be the host (out of scope: single player first).
10. **Strings**: game text is always in the game language; the mod's own words are English
    (localization is M8). The machinery is in place (Core/Strings header: whole phrases, lists,
    sentences, numbers and plural forms per language), but no second table exists and the game
    language is not detected yet (Strings uses "en" rules).
11. **Click hints** (fractions of the window) were measured at 2560x1600 (16:10); menus with
    CustomEvent buttons (EULA accept, options tabs) may miss on other aspect ratios (the hover
    check refuses wrong clicks, but then the button cannot be activated).
12. **The controlled character** is the UI's SelectedCharacter (Entities.Controlled). The
    ClientControl component is not it (stayed on Tav while Lae'zel was selected).
13. **Area estimates** use stats shapes (AreaRadius, Zone Cone/Square) and a 0.5 m body margin;
    the game's real area can differ (height, obstacles, spells that spare allies).
14. **Hover aim points**: entity origin raised by heights, then points across the visual's world
    box (Visual.Visual.WorldBound). Objects whose visible part is outside that box are still
    unreachable.
15. **Travel stops when combat starts** and re-centers the camera (Home) when the character is
    outside the middle half of the screen.

## 7. Harness recipes (tools/game.py)

- Start: `python tools/game.py launch`; splash needs a key: `press space`; Continue:
  `press home down enter` on the main menu (Continue is the 2nd button once saves exist).
- Hot reload Lua: `python -c "import sys; sys.path.insert(0,'tools'); import deploy; deploy.sync_loose()"`
  then `python tools/game.py lua "Ext.Debug.Reset()"`. Native changes need `stop` + `deploy.py`.
- Reset the fight: `python tools/game.py lua "Ext.Input.InjectKeyPress('F8')"` (quick load).
- Speech heard: `python tools/game.py log 20`; bridge events (screens, travel clicks): `blog`.
- Mod keys (config v2): `ctrl+m` (menu), `ctrl+r` (read screen), `ctrl+d` (details); other
  commands through the menu or the dev channel (see session 4).
- Mouse moves are refused unless the game is in the foreground: `lua` does not focus it
  (`press` does). Click traces: `lua "BG3Access.Config.values.debug.traceClicks=true"`, then `blog`.
- Server probes: `lua-server "<code>"` / `lua-server-file <path>` (Osiris available there).
